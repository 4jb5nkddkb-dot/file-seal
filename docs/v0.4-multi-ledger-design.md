# v0.4 多账本设计基线

关联任务：[#4](https://github.com/4jb5nkddkb-dot/file-seal/issues/4)
开发分支：`feat/v0.4-multi-ledger`

## 目标

让 file-seal 支持多个相互隔离的命名账本，同时保持每个账本独立的 genesis hash、序号和哈希链。旧版无哈希链账本必须通过显式迁移进入新格式，原文件不可被覆盖。

## 初步数据模型

```text
LedgerId
LedgerMetadata {
    id: LedgerId
    display_name: String
    schema_version: u32
    created_at: DateTime<Utc>
    ledger_path: PathBuf
}
LedgerStore {
    metadata: LedgerMetadata
    records: Vec<SealRecord>
}
```

账本名称只允许安全字符集，并通过受控的 `ledgers/` 目录解析，禁止把未经校验的用户输入直接拼接为路径。

## CLI 草案

```text
file-seal ledger list
file-seal ledger create <name>
file-seal ledger verify <name>
file-seal ledger migrate <legacy-file> --to <name>
file-seal seal <path> --ledger <name>
file-seal verify <path> --ledger <name>
```

## 迁移边界

迁移必须：

1. 保留旧账本原文件和原始 hash；
2. 写入临时目标并在完成验证后原子替换；
3. 记录迁移时间和源账本摘要；
4. 明确声明“目标链从迁移时刻开始可信”；
5. 遇到损坏行、重复序号或非法记录时失败关闭。

迁移不能声称证明旧账本在迁移前没有被修改。
